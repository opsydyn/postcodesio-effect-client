---
title: Use with Node.js or Bun
description: Choose the right HTTP client for Node.js or Bun server-side applications.
---

`PostcodesClient.Default` uses `FetchHttpClient`, which delegates to the global `fetch`.

**Running in Bun?** Bun implements `fetch` natively — `.Default` is already using
Bun's own high-performance HTTP stack. No extra package needed, nothing to configure.

**Running in Node.js?** Node.js has its own native HTTP client (undici). You may
prefer it for consistency with other Node.js networking, HTTP/2 support, or tuned
connection pooling.

## When to swap the HTTP client

Use `PostcodesClient.layer` — not `.Default` — when you want to supply Node.js's
native client explicitly.

## Install the optional peer dependency

```bash
npm install @effect/platform-node
```

## Wire it up

```typescript
import { Effect, Layer } from "effect"
import { NodeHttpClient } from "@effect/platform-node"
import { PostcodesClient, makeApiConfig } from "@effect-postcodes/client"

const AppLayer = PostcodesClient.layer(
  makeApiConfig({ baseUrl: "https://api.postcodes.io" })
).pipe(
  Layer.provide(NodeHttpClient.layer)
)

const program = Effect.gen(function*() {
  const { lookupPostcode } = yield* PostcodesClient
  return yield* lookupPostcode("EC1A1BB")
}).pipe(
  Effect.provide(AppLayer)
)
```

`PostcodesClient.layer` bundles the in-memory rate limiter but requires you to supply
the HTTP client — that is why `Layer.provide(NodeHttpClient.layer)` is chained after.

## Using in an Effect application

If your application already has a `Layer` composition, merge `AppLayer` into your
existing layer graph:

```typescript
const MainLayer = Layer.mergeAll(
  AppLayer,
  DatabaseLayer,
  // ...
)
```

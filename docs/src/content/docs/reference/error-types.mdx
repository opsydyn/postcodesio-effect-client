---
title: Error types
description: Errors returned by PostcodesClient methods.
---

All service methods return `Effect<Result, ApiServiceError>` where:

```ts
type ApiServiceError =
  | ApiNotFoundError
  | ApiValidationError
  | HttpClientError
  | SchemaError
  | RateLimiterError
```

## Client-owned errors

`ApiNotFoundError` represents a missing postcode, terminated postcode, Scottish
postcode, outcode, or place. It has `resource`, `identifier`, `message`, and a
404-shaped `cause`. Narrow it with `isApiNotFoundError`.

`ApiValidationError` represents invalid client input before a request is made.
It has `field` and `message`; for example, bulk lookup must receive 1–100
postcodes and postcode search must use exactly one of text search or complete
coordinates. Narrow it with `isApiValidationError`.

```ts
import { Effect } from "effect";
import { isApiValidationError } from "@opsydyn/effect-postcodes-client";

const result = yield* client.bulkLookupPostcodes([]).pipe(
	Effect.catchIf(isApiValidationError, (error) => Effect.fail(error.message)),
);
```

## Effect runtime errors

`HttpClientError` covers network and transport failures. `SchemaError` means an
upstream response did not match the expected runtime schema. `RateLimiterError`
can surface when a supplied rate-limiter store fails.

Use the guards and error types exported by Effect's corresponding modules when
you need to handle those cases explicitly.
